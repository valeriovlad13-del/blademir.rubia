PROJECT OVERVIEW

A practical application of switching logic and embedded control.

Purpose

The project demonstrates how switching logic can be combined with a microcontroller and Bluetooth communication to provide mobile control of connected electrical loads.

Control Concept

Commands from the mobile interface are transmitted through the HC-05 Bluetooth module to the Arduino Nano, which operates the relay outputs connected to the demonstration loads.

Mobile Interface

The MIT App Inventor interface shown in the project presents a connected status and ON/OFF controls for the system and connected loads, together with a voice-control interface.

Electrical Demonstration

The system diagram shows a 220 V AC supply for the loads and a separate 5 V, 2 A adapter supplying the low-voltage control electronics.

CONTROL PROGRAM

Bluetooth commands, relay states, and saved settings.

Command mapping

The Arduino receives single-character commands from the HC-05 serial connection. Each load has an uppercase/lowercase command pair, while the E/e pair controls the system power state.

A / a → Load 1 B / b → Load 2 C / c → Load 3 D / d → Load 4 E / e → Power

EEPROM state storage

The program stores the four load states and the power state in EEPROM addresses 1–5. When the Arduino starts, those saved values are read back so the control state can be restored.

Arduino Nano control logic HC-05 • EEPROM • 4-Channel Relay 
#include <EEPROM.h>
#include <SoftwareSerial.h>

SoftwareSerial BT_Serial(2, 3); // RX, TX

const byte RELAY_1 = 4;
const byte RELAY_2 = 5;
const byte RELAY_3 = 6;
const byte RELAY_4 = 7;

char btData = '0';

int load1 = 0;
int load2 = 0;
int load3 = 0;
int load4 = 0;
int powerState = 0;

void setup() {
    Serial.begin(9600);
    BT_Serial.begin(9600);

    pinMode(RELAY_1, OUTPUT);
    pinMode(RELAY_2, OUTPUT);
    pinMode(RELAY_3, OUTPUT);
    pinMode(RELAY_4, OUTPUT);

    // Initial relay state.
    digitalWrite(RELAY_1, HIGH);
    digitalWrite(RELAY_2, HIGH);
    digitalWrite(RELAY_3, HIGH);
    digitalWrite(RELAY_4, HIGH);

    // Restore the last saved states.
    load1 = EEPROM.read(1);
    load2 = EEPROM.read(2);
    load3 = EEPROM.read(3);
    load4 = EEPROM.read(4);
    powerState = EEPROM.read(5);

    // Use valid 0/1 states if EEPROM has not been initialized yet.
    if (load1 > 1) load1 = 0;
    if (load2 > 1) load2 = 0;
    if (load3 > 1) load3 = 0;
    if (load4 > 1) load4 = 0;
    if (powerState > 1) powerState = 0;

    delay(500);
}

void loop() {
    if (BT_Serial.available() > 0) {
        btData = BT_Serial.read();
    }

    switch (btData) {
        case 'A': load1 = 0; EEPROM.update(1, load1); break;
        case 'a': load1 = 1; EEPROM.update(1, load1); break;

        case 'B': load2 = 0; EEPROM.update(2, load2); break;
        case 'b': load2 = 1; EEPROM.update(2, load2); break;

        case 'C': load3 = 0; EEPROM.update(3, load3); break;
        case 'c': load3 = 1; EEPROM.update(3, load3); break;

        case 'D': load4 = 0; EEPROM.update(4, load4); break;
        case 'd': load4 = 1; EEPROM.update(4, load4); break;

        case 'E': powerState = 0; EEPROM.update(5, powerState); break;
        case 'e': powerState = 1; EEPROM.update(5, powerState); break;
    }

    btData = '0';

    // Power-state logic.
    if (powerState == 1) {
        digitalWrite(RELAY_1, HIGH);
        digitalWrite(RELAY_2, HIGH);
        digitalWrite(RELAY_3, HIGH);
        digitalWrite(RELAY_4, HIGH);
    } else {
        digitalWrite(RELAY_1, load1);
        digitalWrite(RELAY_2, load2);
        digitalWrite(RELAY_3, load3);
        digitalWrite(RELAY_4, load4);
    }

    // Send the current states back to the MIT App Inventor interface.
    BT_Serial.print(powerState);
    BT_Serial.print(';');
    BT_Serial.print(load1);
    BT_Serial.print(';');
    BT_Serial.print(load2);
    BT_Serial.print(';');
    BT_Serial.print(load3);
    BT_Serial.print(';');
    BT_Serial.print(load4);
    BT_Serial.println(';');

    delay(500);
}
This is a cleaned-up presentation version of the supplied Arduino program. The control mapping and EEPROM state-storage approach are retained, while naming, formatting, the command handler, and EEPROM writes are made easier to read. The startup logic also validates EEPROM values so an uninitialized EEPROM does not produce invalid relay states. EEPROM.update() is used instead of writing the same value repeatedly, which avoids unnecessary EEPROM writes when the stored byte has not changed.
